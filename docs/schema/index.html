The catalog joins reusable patterns to storage engines, records alternative approaches, and tracks hands-on attempts. This is the live schema implemented by db.go and the behavior exposed by the store and CLI.

Relationship and lifecycle rules

Cardinality

  • A pattern has many approaches and many attempts.
  • An engine has many approaches and many attempts.
  • An approach belongs to one pattern and one engine.
  • An attempt belongs to one pattern and one engine; it cites zero or one approach.

Attempt integrity

approaches UNIQUE(id, pattern_id, engine_id) exists solely as the parent key for the attempt composite FK. This prevents an attempt from pointing at an approach for a different pair, even though approach_id alone is globally unique.

Deletes through the CLI

  • Removing a pattern or engine with dependents requires --force; the database then cascades to its approaches and attempts.
  • Removing an approach runs a transaction that first sets citing attempts’ approach_id to NULL and updates their timestamps, then deletes the approach.
  • Removing an attempt deletes only that attempt.

Indexes

patterns_family(family); partial unique patterns_curriculum_order_unique(curriculum_order) for non-NULL positions; approaches_pattern(pattern_id); approaches_engine(engine_id); attempts_pattern(pattern_id); attempts_engine(engine_id); attempts_status(status).

Direct SQL caveat

The composite FK has no ON DELETE action, so SQLite’s default NO ACTION applies to a directly deleted cited approach. The CLI’s explicit unlink is what preserves attempts when an approach is removed. Foreign-key enforcement is enabled by openDB.

Migration history

Idempotent startup

schemaSQL creates missing tables and indexes only. On every open, ordered idempotent migrations fill schema gaps in existing databases.

patterns.explanation and patterns.use_cases

Added as required TEXT with default '' when absent.

patterns.readings

Added as a required JSON-array TEXT column with default []; existing legacy non-JSON values are split into lines and rewritten as reading objects.

patterns.invariant → invariants

Legacy single-text invariant is converted line-by-line into the JSON-array invariants column, then the old column is dropped.

patterns.curriculum_order

A nullable positive-integer column is added to older databases in a transaction, followed by the partial unique index CREATE UNIQUE INDEX patterns_curriculum_order_unique ON patterns (curriculum_order) WHERE curriculum_order IS NOT NULL. The migration is idempotent and leaves newly upgraded rows NULL until seeding or reconciliation assigns positions. If an existing order column or index has an incompatible definition, opening fails instead of accepting weaker constraints.

Source of truth: db.go defines DDL and migrations; store.go defines typed reads, JSON handling, timestamps, ordering, and joins; the command handlers define deletion workflow. See the relationship map for the diagram.
