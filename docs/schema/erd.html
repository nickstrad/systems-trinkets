Every attempt has its own pattern and engine. Its optional approach reference is deliberately a three-column foreign key, so an attempt cannot quietly point across pairs.

The guarded link: attempts(approach_id, pattern_id, engine_id) references approaches(id, pattern_id, engine_id). If approach_id is NULL, SQLite skips that check; otherwise all three values must identify the same approach row.

What deletes do

Pattern or engine removal

Both are direct parents of approaches and attempts. Their foreign keys use ON DELETE CASCADE, so deleting either parent deletes its dependent rows. The CLI requires --force when such dependents exist.

Approach removal

The approach reference has SQLite’s default NO ACTION, not a cascade or set-null clause. The CLI deliberately unlinks dependent attempts in one transaction—setting approach_id = NULL and updating updated_at—before deleting the approach.

Checks and indexes

  • Pattern JSON fields must be JSON arrays.
  • Attempt status is planned, in_progress, done, or abandoned.
  • Indexes support pattern/engine joins plus pattern family and attempt status filtering.
  • Foreign keys are enabled by the connection DSN in openDB.
